# MediaForge design and compression review

Date: 2026-10-19. Status: implemented locally, awaiting user design acceptance before commit/push.

## Design

A restrained utility interface with a small header, normal text sizes, neutral gray colors,
underlined navigation and a direct file-selection workflow. Light is the default theme;
a neutral dark theme is available. No hero headline, marketing slogans, numbered navigation,
decorative arrows or colored panels. Empty job details appear only after selecting a job.
The third revision uses compact segmented quality controls with a single explanation,
flat file rows, readable German job statuses and searchable format choices. Native modal
dialogs support Escape, focus restoration and keyboard cycling. Tabs expose their associated
panel and support keyboard navigation. Motion is limited to a sliding tab underline, short
menu/dialog entrances and transform-based progress indicators; reduced-motion settings disable
these transitions. Mobile format menus stay within the viewport and scroll internally.
Existing logo and application workflows retained. The compression workspace retains its
selection when switching tools. Desktop and 320 px mobile layouts reviewed visually.

References inspected in the browser:

- https://pairdrop.net/ (minimal utility layout)
- https://squoosh.app/ (direct file-first workflow; decorative styling not adopted)

## Verification

- TypeScript typecheck and Vite production build.
- Python API/worker suite: 128 passed; one existing symlink test skipped because the local
  Windows environment cannot create the required symlink.
- Chromium Playwright suite: 24 passed, including existing download/conversion/history flows
  and new mixed compression batches, independent settings, retry after server error, selection
  retention, per-file removal, completed batch ZIP download, format search and empty results,
  dialog keyboard focus, reduced motion and responsive screenshot checks.
- Actual FFmpeg encoding and decoding for all offered media compression targets: MP4, WebM,
  MKV, Opus, MP3, M4A, FLAC, WebP, AVIF, JPG and PNG.
- Actual Ghostscript PDF compression with page-count and output-size checks.
- ZIP/GZIP/XZ round trips verify byte-identical input recovery; native Office/OpenDocument/EPUB
  package tests verify entry content and preservation of the uncompressed mimetype entry.
- HTTP multipart upload through the real API handler and synchronous worker to downloadable
  output; failure path verifies failed status and removal of uploaded/partial files.
- Visual inspection of the simplified revision covered light/dark desktop views, uploaded-file
  settings and narrow mobile views. Removed redundant empty states and excessive decoration.

Screenshots are generated by `apps/frontend/tests/e2e/compression.spec.ts` and
`apps/frontend/tests/e2e/interface.spec.ts` under the ignored `tmp/design-review/` folder.
Current revision screenshots start with `v3-`. The Impeccable inspection identified one animated
layout property; progress now animates with transforms. The final confirmation passed the
24-test browser suite, typecheck and production build, followed by screenshot review.
UI review uses controlled API fixtures and sample filenames.
The Python integration tests use actual conversion engines and a stubbed clean malware scanner.

## Verification boundaries

Docker is not installed in this local environment. The complete Linux Compose deployment,
Redis/Celery broker delivery, live ClamAV service and external-site downloads were not exercised
here. Existing scanner/network tests pass, but this is not a claim of a live production-stack
test or of perfect results for every possible input/codec. The deployment should rebuild the
worker to install Ghostscript and run the existing release smoke checks.

No production data, live services or remote repository were changed. Push remains gated on
the user's requested acceptance.
